# Спецификация: управляемая загрузка модели GigaAM

Статус: реализовано в 0.3.0. Область: одна модель `v3_e2e_rnnt`.

## 1. Проблема

Провайдер `gigaam-local` не имел объекта `preparation`, поэтому сервис
`speechToText` отдавал в UI `{ phase: "ready" }` независимо от состояния диска:

1. **Ложная готовность.** Микрофон выглядел рабочим, но первое распознавание
   «висело» 20–30 с, пока воркер молча качал 428 МБ. Согласия на трафик,
   прогресса и отмены не было.
2. **Ошибки без диагностики.** Отсутствие Python-окружения или сбой сети
   выяснялись уже после записи.
3. **Нет управления диском.** Ни оценок, ни пути к кэшу.

У SenseVoice-провайдера это решено: `check → model/vad → verify → load`,
прогресс, отмена, выбор источника. Нужен паритет.

## 2. Цели

- Пользователь явно решает скачать модель: видит размер, время, память, диск.
- Прогресс и отмена; по завершении — `ready`, первое распознавание без задержки.
- Понятные ошибки: нет окружения, сеть, диск, целостность.
- Одна модель, без выбора и без «зоопарка» в интерфейсе.

Не цели: установка Python/torch из UI, потоковое распознавание, GPU,
автообновление моделей, удаление моделей из UI.

## 3. Решение: одна модель

Единственная модель — **GigaAM v3 E2E RNNT** (`v3_e2e_rnnt`): русский, с
пунктуацией и заглавными. Другие модели (CTC, multilingual, SSL) в UI не
предлагаются и автоматически не скачиваются; при необходимости их можно
поставить вручную через `python/setup.sh <model>` и указать в конфиге строки.

| Параметр | Значение |
| --- | --- |
| Файл | `v3_e2e_rnnt.ckpt`, 448 929 252 Б (428 МБ) |
| MD5 | `2730de7545ac43ad256485a462b0a27a` |
| Токенизатор | `v3_e2e_rnnt_tokenizer.model`, 255 336 Б |
| SHA-256 токенизатора | `828c12c991019eef952a960661f25a92d6ad279591e2ea466b4aeddf1d20a18a` |
| Источник | `https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/` |
| Лицензия | MIT (SberDevices) |

Провайдер один: `gigaam-local`, имя в списке — **GigaAM v3 · Russian
(punctuation)**. Языки: `auto`, `ru`, `en`.

## 4. Состояния подготовки

Провайдер отдаёт объект `preparation` со `snapshot()`, `subscribe()`,
`prepare({downloadSource})` и `cancel()`. Схема состояний повторяет
SenseVoice-провайдер, чтобы UI отрисовал карточку и прогресс без доработок.

```
checking → unprepared → downloading → verifying → loading → ready
                     ↘ failed / cancelled        ↘ standby (файлы уже есть)
```

- **Активация** выполняет только `inspect()`: проверяет интерпретатор, скрипт и
  наличие файлов нужного размера. Ничего не скачивает.
- **`unprepared`** — файлов нет; UI показывает карточку с оценками и кнопкой
  «Download and prepare».
- **`downloading`** — по файлу: `resource`, `completedBytes`, `totalBytes`,
  прогресс не чаще 100 мс.
- **`verifying`** — размер + MD5/SHA-256; при расхождении файл удаляется и
  состояние `failed` с `download.reason = "integrity"`.
- **`loading`** — `python gigaam_stt.py --warmup` (проверяет MD5 и грузит модель).
- **`ready`** — всё проверено и загружено; **`standby`** — файлы на месте, но
  модель ещё не грузилась (запись это разбудит).
- **`failed`** — `message` + `download: {resource, source, reason, code?, status?}`,
  где `reason` ∈ `network | dns | timeout | certificate | storage | http | integrity | unknown`.
- **`cancelled`** — отмена прерывает fetch и процесс, частичный `.part`
  удаляется; повторная попытка начинает файл заново.

`prepare()` идемпотентен: готовые файлы не перекачиваются, но проверяются
хешем. Параллельный вызов присоединяется к активной задаче. Смена источника во
время задачи отклоняется.

## 5. Источник и проверки

- `info.downloadSources` = `["https://cdn.chatwm.opensmodel.sberdevices.ru"]`.
  UI показывает выбор источника, только если их больше одного; сейчас — один.
- URL файла: `<origin>/GigaAM/<name>`.
- Перед скачиванием проверяется, что запрошенный источник входит в
  `downloadSources` (иначе `failed`).
- Целостность: MD5 чекпойнта (совпадает с проверкой самого пакета `gigaam`) и
  SHA-256 токенизатора (значение из HF-блоба).

## 6. Оценки в карточке

`setupEstimate`: диск 500 МБ (UI показывает «0.5 GB»), память 1.5 ГБ, время
1–5 минут. После установки: диск ~0.43 ГБ модель + 2.5 ГБ окружение.

## 7. UX до/после

| Сценарий | Было | Стало |
| --- | --- | --- |
| Первый запуск | «Готово», первое распознавание висит без объяснений | Карточка «Скачать 428 МБ, 1–5 мин, 1.5 ГБ RAM» → прогресс → «Готово» |
| Нет модели | Молчаливая загрузка в воркере | Явный `unprepared`, запись заблокирована до подготовки |
| Нет Python | Ошибка после записи | `failed` с текстом «Run python/setup.sh first» |
| Плохая сеть | Таймаут | Причина + повтор; проверка источника |
| Битый файл | Падение при загрузке модели | `failed` с `integrity`, файл удалён, повторная попытка чистая |
| Отмена | Не было | Кнопка Cancel, `.part` удаляется |

## 8. Что остаётся вне UI

Python-окружение (torch + `gigaam`, ~2.5 ГБ) ставится `python/setup.sh`:
pip-установка идёт 5–15 минут, требует компиляторов и плохо переживает отмену.
`check`-шаг обязан явно сообщать об отсутствии окружения — это реализовано.

## 9. Реализация (0.3.0)

| Файл | Роль |
| --- | --- |
| `lib/config.js` | пути, каталог файлов, хеши, источники, нормализация конфига |
| `lib/preparation.js` | `inspect`, `prepare`, `cancel`, прогресс, проверка, классификация ошибок |
| `lib/worker.js` | Python-воркер, очередь, отмена, warm-up |
| `lib/index.js` | регистрация провайдера с `preparation` |
| `test/preparation.mjs` | 6 тестов на локальном HTTP-сервере |

## 10. Тесты

- `inspect` на пустом кэше → `unprepared`; без интерпретатора → `failed`.
- `prepare` с локальным сервером: прогресс, `ready`, файл на диске, повтор не
  качает второй раз.
- Неверный хеш → `failed`, `download.reason = "integrity"`, файла нет.
- Отмена во время медленной загрузки → `cancelled`, `.part` удалён.
- Неизвестный источник → `failed` до скачивания.
- Реальный прогон на существующем кэше: `inspect` → `standby`, `prepare` →
  `ready` за ~3 с (проверка + warm-up).

## 11. Известные ограничения

- Языковой список `auto/ru/en`: клиент DSH не локализует код `ru` и покажет его
  как «ru» — косметика, повлиять из провайдера нельзя.
- Отмена не делает resume: повторная загрузка начинается с нуля (Range — 0.4).
- Удаления моделей из UI нет.
